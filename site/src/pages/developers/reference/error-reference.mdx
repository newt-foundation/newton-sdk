# Error Reference [Newton Protocol error codes, messages, and resolution steps]

This page documents all error codes and messages you may encounter when interacting with the Newton Protocol Gateway, SDK, and smart contracts.

## Gateway Errors

The gateway does not return numeric JSON-RPC error codes. A failed call returns an HTTP error status and a JSON-RPC body whose `error` names the gateway's error variant:

```json
{
  "jsonrpc": "2.0",
  "result": null,
  "error": { "AuthorizationFailed": "RpcWrite permission required" },
  "id": null
}
```

[Error Codes](/developers/reference/rpc-api#error-codes) in the RPC API reference lists every variant with its HTTP status. The SDK raises these errors as a [`GatewayError`](#gatewayerror).

A task that fails evaluation is not a gateway error. `newt_createTask` returns HTTP 200 with `status` set to `failed` and the reason in `error`, and the SDK throws a plain `Error` that names the task and the reason: `newt_createTask failed for task <taskId>: <reason>`.

### Gateway Error Messages

| Error | Cause | Resolution |
|---|---|---|
| `{"InvalidRequest":"Unknown Newton RPC method: <method>"}` | Typo in method name | Verify method spelling against [RPC API](/developers/reference/rpc-api) |
| `{"InvalidRequest":"Invalid request format: <details>"}` | Malformed request parameters | Review parameter types and required fields |
| `{"AuthenticationFailed":"missing or invalid API key"}` | The request has no API key | Send the key in an `Authorization: Bearer` or `X-API-Key` header |
| HTTP 401 with an empty body | The API key does not match any key | Verify the key or create a new one in the [Dashboard](/developers/overview/dashboard-api-keys) |
| `{"AuthorizationFailed":"RpcRead permission required"}` | API key lacks read permission | Use key with `rpc_read` or `rpc` permission |
| `{"AuthorizationFailed":"RpcWrite permission required"}` | API key lacks write permission | Use key with `rpc_write` or `rpc` permission |
| `{"AuthorizationFailed":"policy client <client> is owned by <owner>, not by caller <caller>"}` | The wallet address on your API key is not the policy client's onchain `getOwner()` | Use the API key whose wallet address owns the policy client |
| `{"AuthorizationFailed":"API key has no configured wallet address; cannot verify policy client ownership"}` | The key has no wallet address, so the gateway cannot check ownership | Use a key with a configured wallet address |
| `{"InvalidRequest":"wasm_args count (<n>) must match the policy set (<m>); one entry per policy, empty for pure-Rego"}` | `wasm_args` length differs from the policy client's policy set | Send one entry per policy, in set order |
| `{"InvalidRequest":"proof_cid is unsupported; zkTLS proof verification is unavailable"}` | The request has a `proof_cid` | Remove `proof_cid` |
| `{"Timeout":<seconds>}` | The gateway stopped waiting for the operation | Retry the request |
| `"RateLimitExceeded"` | Too many requests for this API key | Back off and retry |

## On-Chain Errors

| Error | Contract | Cause | Resolution |
|-------|----------|-------|------------|
| `InvalidAttestation()` | PolicyClient | BLS signature verification failed | Verify Task Manager address, check attestation expiration |
| `ExecutionFailed()` | PolicyClient | Inner transaction call reverted | Debug the target transaction independently |
| `PolicyClientNotRegistered` | PolicyClientRegistry | Client not registered or has been deactivated | Register via `registerClient()` or CLI: `newton-cli policy-client register`. See [PolicyClientRegistry](/developers/guides/smart-contract-integration#policyclientregistry) |
| `EmptyPolicySet` | PolicyClient | Empty replacement | Supply at least one spec |
| `TooManyPolicies` | PolicyClient | More than 8 policies in pinned release | Reduce the set size |
| `PolicyNotRegistered` | PolicyClient | Address not registered by configured factory | Verify TaskManager `policyFactory()` and factory `isPolicy` |
| `PolicyFactoryNotSet` | PolicyClient | Missing TaskManager or factory | Configure the correct deployment |
| `ZeroExpireAfter` | PolicyClient | A spec has zero expiry | Set a nonzero block window |
| `PolicyParamsTooLarge` | PolicyClient | Params exceed 65,536 bytes | Reduce encoded params |
| `OnlyPolicyClientOwner` | PolicyClient | Unauthorized replacement | Submit through the current owner |
| `PolicyDenied` | TaskManager | Aggregate decision is false | Inspect per-policy simulation results; do not execute |
| `TaskAlreadyExists(bytes32)` | TaskManager | Duplicate task submission | Use a different nonce or wait for existing task |
| `Not authorized intent sender` | PolicyClient | `msg.sender` does not match `attestation.intent.from` | Ensure the user who signed the intent is the transaction sender |
| `Chain ID does not match` | PolicyClient | Attestation was created for a different chain | Verify the intent specifies the correct `chainId` |
| `Attestation expired` | TaskManager | `block.number >= attestation.expiration` | Request a new attestation; consider increasing `expireAfter` in policy config |
| `Attestation already spent` | TaskManager | Attestation has already been used | Each attestation is single-use; request a new one |
| `InterfaceNotSupported` | PolicyClient | Contract does not implement `IERC165` correctly | Override `supportsInterface` and call `super.supportsInterface(interfaceId)` |

### On-Chain Error Selectors

When `_validateAttestationDirect()` reverts, the error can originate from the PolicyClient, TaskManager, or AttestationValidator. Standard ABI decoders (including viem) may show "Unable to decode signature" because these selectors are not in your contract's ABI.

| Selector | Error | Meaning |
|----------|-------|---------|
| `0xec9758ff` | `InsufficientQuorumStake()` | Operators lack registered on-chain stake |
| `0x716dcc39` | `AttestationExpired()` | Attestation expired before tx was mined |
| `0x297fb567` | `AttestationHashMismatch()` | Task/response hash does not match attestation |
| `0x2a5d4fed` | `AttestationAlreadySpent()` | This attestation was already used |
| `0xf984c150` | `CertificateMessageHashMismatch()` | BLS certificate hash mismatch |
| `0x729d0f6b` | `SignatureVerificationFailed()` | BLS signature invalid |
| `0x90fe746d` | `ClientNotRegistered(address)` | Vault not in PolicyClientRegistry |

Use `cast sig "ErrorName()"` to compute selectors for new errors.

## SDK Errors

The SDK throws these error classes, all exported from `@newton-xyz/sdk`:

| Class | Thrown when |
|---|---|
| `GatewayError` | A gateway JSON-RPC call fails. See [GatewayError](#gatewayerror) |
| `SDKError` | The SDK rejects an argument or a gateway response. `code` is an `SDKErrorCode` |
| `DelegatorError` | A newton-delegator call fails. See [Delegated Intents](/developers/guides/delegated-intents) |
| `MagicRPCError` | The Newton Wallet popup returns an error, or the user closes it |

Other failures, such as an unsupported chain, a missing contract address or a task that fails evaluation, throw a plain `Error` whose message names the cause.

### GatewayError

| Property | Type | Description |
|---|---|---|
| `method` | `string` | The JSON-RPC method, for example `newt_createTask` |
| `status` | `number` | HTTP status of the response |
| `code` | `string` | The gateway's error variant, for example `AuthorizationFailed` or `RateLimitExceeded`. `http_error` for an error status without a JSON-RPC body, such as the empty-body 401 for an unknown API key. `malformed_response` for a success status whose body has no `result` |
| `rawMessage` | `string` | The variant's message. For `http_error`, the first 4,096 characters of the response body, else the status text, else `empty body` |
| `data` | `unknown` | The variant's value, for example the seconds waited for `Timeout`. For `malformed_response`, the response body |
| `retryAfter` | `number \| undefined` | The `Retry-After` header in seconds. The gateway sends it with `ServiceOverloaded` |

### SDKError Codes

| Code | Thrown when |
|---|---|
| `MALFORMED_RESPONSE` | `evaluateIntentDirect` gets a `newt_createTask` result without a `task_response` |
| `INVALID_ARGUMENT` | `simulatePolicyData` gets a `secrets` string that is not JSON, or `submitIntentAndSubscribe` gets an API key that a WebSocket subprotocol cannot carry |
| `POPUP_ALREADY_EXISTS` | A Newton identity popup is already open |
| `MISSING_CHAIN` | An identity link or unlink function gets a wallet client without a chain |
| `MISSING_ACCOUNT` | An identity link or unlink function gets a wallet client without an account |
| `INVALID_ADDRESS` | The SDK has no IdentityRegistry address for the wallet client's chain |

`SDKErrorCode` also defines `MISSING_API_KEY`, `EXTENSION_NOT_INITIALIZED`, `INCOMPATIBLE_EXTENSIONS`, `FAILED_TO_OPEN_POPUP` and `FAILED_TO_RETRIEVE_NATIVE_TOKEN_BALANCE`. The SDK does not throw them.

```ts twoslash
import { createWalletClient, http } from 'viem';
import { privateKeyToAccount } from 'viem/accounts';
import { sepolia } from 'viem/chains';
import {
  GatewayError,
  newtonWalletClientActions,
  SDKError,
  SDKErrorCode,
} from '@newton-xyz/sdk';

const walletClient = createWalletClient({
  account: privateKeyToAccount('0x' + '1'.repeat(64) as `0x${string}`),
  chain: sepolia,
  transport: http('https://eth-sepolia.g.alchemy.com/v2/demo'),
}).extend(newtonWalletClientActions({ apiKey: 'test-api-key' }));

const request = {
  policyClient: '0x1234567890123456789012345678901234567890',
  intent: {
    from: '0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266',
    to: '0xb1aD5f82407bC0f19f42b2614fb9083035a36b69',
    value: '0x0',
    data: '0x',
    chainId: 11155111,
    functionSignature: '0x',
  },
  wasmArgs: ['0x'] as `0x${string}`[],
  timeout: 30,
} as const;
// ---cut---
try {
  await walletClient.evaluateIntentDirect(request);
} catch (error) {
  if (error instanceof GatewayError) {
    // The gateway rejected the call: code is the error variant, status the HTTP status
    if (error.code === 'RateLimitExceeded') {
      // Back off and retry
    }
  } else if (error instanceof SDKError && error.code === SDKErrorCode.MalformedResponse) {
    // The gateway answered without a task response
  } else if (error instanceof Error) {
    // The task failed evaluation: error.message is the gateway's reason
  }
}
```

## HTTP Status Codes

| Status | Description |
|--------|-------------|
| 200 | Success. A method can still report a failed evaluation in its result, for example `status: "failed"` from `newt_createTask` or `success: false` from the simulate methods |
| 400 | `InvalidRequest`, or a body that is not valid JSON |
| 401 | `AuthenticationFailed`, for example when the request has no API key; an empty body when the key does not match any key |
| 403 | `AuthorizationFailed`: the key lacks a permission or does not own the policy client |
| 408 | The request ran past the server request timeout (30 seconds in the default configuration) |
| 413 | The request body is larger than the gateway's body limit |
| 415 | The request has no `Content-Type: application/json` header |
| 422 | `IncompatiblePolicyVersion`, or a body that does not match the JSON-RPC request shape |
| 429 | `RateLimitExceeded` |
| 500 | `Internal`, `DatabaseError` and the other server-side variants |
| 502 | `BadGateway` or `AllOperatorsFailed` |
| 503 | `ServiceUnavailable`, `ServiceOverloaded` (with a `retry-after` header) or `CircuitBreakerOpen`; an empty body when the gateway could not look up the API key |
| 504 | `Timeout` |

## Diagnostic Tools

- **`newton-cli regorus eval`** — test Rego policies locally with Newton crypto extensions
- **`newton-cli policy simulate`** — test full policy evaluation locally
- **`newton-cli policy-data simulate`** — test WASM oracle execution locally
- **`newt_simulatePolicy`** — test policy evaluation via the Gateway
- **`newt_simulatePolicyData`** — test WASM execution via the Gateway
- **[Newton Explorer](https://explorer.newton.xyz)** — view task status and evaluation results
- **[Explorer API](/developers/reference/explorer-api)** — script task and policy lookups with your API key
