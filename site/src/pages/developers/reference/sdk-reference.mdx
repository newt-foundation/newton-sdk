# Newton Protocol SDK Reference

Official TypeScript SDK for the Newton Protocol. This page provides a complete reference for all exported methods, types, interfaces, and utilities in the `@newton-xyz/sdk` package.

:::info
The SDK integrates with [viem](https://viem.sh) by extending `PublicClient` and `WalletClient` instances with Newton-specific actions. Make sure you are familiar with viem basics before proceeding.
:::

---

## Policy-set requests

This reference covers the SDK release after **1.3.1**; sections note where 1.3.1 and earlier differ. `submitEvaluationRequest`, `evaluateIntentDirect`, `submitIntentAndSubscribe`, `simulateTask`, and `simulatePolicy` require `wasmArgs: Hex[]`, positionally aligned with the client's ordered set. Pass `['0x']` for one pure-Rego policy and `['0x', '0x']` for two. A scalar or omitted value is not supported by these SDK methods.

```ts
interface PolicyConfig { policyParams: Hex; expireAfter: number }
interface PolicySpec { policy: Address; config: PolicyConfig }
```

Call `publicClient.getPolicySetSnapshot({ policyClientAddress })` when you need identity, revision, and specs together. It returns `{ policyId, revision, policies }` from one read. Preserve order and repeated entries in both tasks and responses. Individual oracle simulation methods still use scalar `wasmArgs`.

## Overview

The SDK is organized into two main client extensions:

| Extension                   | Purpose                                                | Client Type    |
| --------------------------- | ------------------------------------------------------ | -------------- |
| `newtonPublicClientActions` | Read-only operations (query tasks, policy state)       | `PublicClient` |
| `newtonWalletClientActions` | Write operations (submit evaluations, manage policies) | `WalletClient` |

For a step-by-step walkthrough of integrating these into your application, see the [Integration Guide](/developers/guides/integration-guide). For the underlying JSON-RPC methods the SDK calls, see the [RPC API Reference](/developers/reference/rpc-api).

## Setup & Initialization

:::info
Newton Protocol currently supports **Ethereum Sepolia** (chain ID `11155111`), **Base Sepolia** (chain ID `84532`), **Robinhood Chain testnet** (chain ID `46630`), **Arc testnet** (chain ID `5042002`), **Ethereum Mainnet** (chain ID `1`), and **Base** (chain ID `8453`). Pass the corresponding `chain` object from `viem/chains` when constructing your clients. If your viem version has no chain object for Robinhood Chain testnet or Arc testnet, build one with viem's `defineChain`.
:::

### newtonPublicClientActions

Extends a viem `PublicClient` with Newton Protocol read methods.

```ts twoslash
import { createPublicClient, http } from 'viem';
import { sepolia, baseSepolia, base } from 'viem/chains';
import { newtonPublicClientActions } from '@newton-xyz/sdk';
// ---cut---
const publicClient = createPublicClient({
  chain: sepolia,        // or baseSepolia, base, mainnet
  transport: http('https://eth-sepolia.g.alchemy.com/v2/demo'),
}).extend(
  newtonPublicClientActions({
    policyContractAddress: '0x1234567890123456789012345678901234567890', // optional
  })
);
```

**Signature:**

```ts
function newtonPublicClientActions(
  options?: {
    policyContractAddress?: Address;
  },
  overrides?: SdkOverrides
): (publicClient: PublicClient) => NewtonPublicClientMethods;
```

**Parameters:**

| Parameter                       | Type           | Required | Description                                           |
| ------------------------------- | -------------- | -------- | ----------------------------------------------------- |
| `options.policyContractAddress` | `Address`      | No       | Scopes all policy read calls to this contract address |
| `overrides`                     | `SdkOverrides` | No       | Override default SDK configuration                    |

### newtonWalletClientActions

Extends a viem `WalletClient` with Newton Protocol write methods.

```ts twoslash
import { createWalletClient, http } from 'viem';
import { privateKeyToAccount } from 'viem/accounts'
import { sepolia, baseSepolia, base } from 'viem/chains';
import { newtonWalletClientActions } from '@newton-xyz/sdk';

const walletClient = createWalletClient({
  account: privateKeyToAccount('0x' + '1'.repeat(64) as `0x${string}`),
  chain: sepolia,        // or baseSepolia, base, mainnet
  transport: http('https://eth-sepolia.g.alchemy.com/v2/demo'),

  newtonWalletClientActions({
    apiKey: 'test-api-key',
    policyContractAddress: '0x1234567890123456789012345678901234567890', // optional
  })

```

```ts

    policyContractAddress?: Address;
  },
```

**Parameters:**

| Parameter                      | Type           | Required | Description                                          |

## Wallet Client Methods (Write)

These methods are available after extending a `WalletClient` with `newtonWalletClientActions`.

### submitEvaluationRequest

Submits an intent evaluation request to the Newton Protocol via the gateway. The task is created onchain and operators evaluate the intent against the policy. Returns a `PendingTaskBuilder` that can be used to await the task response.

```ts
const { result, waitForTaskResponded } = await walletClient.submitEvaluationRequest({
  policyClient: '0x...',
  intent: {
    from: '0x...',
    to: '0x...',
    value: '0x0',
    data: '0x...',
    chainId: '0xaa36a7', // Ethereum Sepolia (11155111)
    functionSignature: '0x...',
  },
  wasmArgs: ['0x'], // One pure-Rego policy
  timeout: 60,
});

console.log(result.taskId);  // Hex

// Optionally wait for the onchain response
const response = await waitForTaskResponded({ timeoutMs: 120000 });
```

**Signature:**

```ts
submitEvaluationRequest(
  args: SubmitEvaluationRequestParams
): Promise<{ result: { taskId: Hex; txHash?: Hex } } & PendingTaskBuilder>
```

**Parameters:**

| Parameter                  | Type               | Required | Description                                                                 |
| -------------------------- | ------------------ | -------- | --------------------------------------------------------------------------- |
| `policyClient`             | `Address`          | Yes      | The policy client contract address                                          |
| `intent`                   | `IntentFromParams` | Yes      | The intent to evaluate                                                      |
| `timeout`                  | `number`           | Yes      | Sent as `timeout`. The gateway accepts it but does not apply it, and ends any HTTP request that runs past its server request timeout (30 seconds in the default configuration) with HTTP 408 |
| `proofCid`                 | `string`           | No       | Deprecated. The gateway rejects any value with `InvalidRequest`: zkTLS proof verification is unavailable |
| `includeValidateCalldata`  | `boolean`          | No       | Include ABI-encoded `validateAttestationDirect` calldata in the response    |

`identityDomain`, `encryptedDataRefs`, `userSignature`, `appSignature`, `userPublicKey`, and `appPublicKey` are deprecated. The gateway has no such fields, and releases after 1.3.1 do not send them. Operators resolve identity data from the domains linked to the signer recovered from `intentSignature`.

**Returns:** An object containing:

- `result.taskId` (`Hex`) -- The unique task identifier
- `result.txHash` (`Hex | undefined`) -- Always `undefined`: `newt_createTask` returns no transaction hash. SDK 1.3.1 and earlier type it as `Hex`, but never set it either
- `waitForTaskResponded({ timeoutMs? })` -- A method to await the onchain attestation result

A task that fails evaluation throws a plain `Error` with the gateway's reason. A call the gateway rejects throws a [`GatewayError`](/developers/reference/error-reference#gatewayerror).

:::note
`newt_createTask` returns `validate_calldata` when you pass `includeValidateCalldata: true` (see the [RPC API Reference](/developers/reference/rpc-api)). The SDK's `submitEvaluationRequest` and `evaluateIntentDirect` wrappers do not surface it: call the gateway RPC directly when you need it.
:::

### evaluateIntentDirect

Evaluates an intent directly through the gateway without waiting for onchain task response confirmation. Pass the results to your policy client's `_validateAttestationDirect`, which calls the Task Manager's `validateAttestationDirect` (`NewtonProverTaskManagerShared`).

```ts
const domain = await readEip712Domain(policyClient, publicClient);
if (!domain) {
  throw new Error(
    "This policy client does not expose an EIP-712 domain, so the app cannot sign an intent for it.",
  );
}

const intent = {
  from: account.address,
  to: '0x...',
  value: '0x0',
  data: '0x',
  chainId: 11155111,
  functionSignature: '0x',
} as const;

const intentSignature = await walletClient.signTypedData({
  account,
  domain,
  types: {
    Intent: [
      { name: 'from', type: 'address' },
      { name: 'to', type: 'address' },
      { name: 'value', type: 'uint256' },
      { name: 'data', type: 'bytes' },
      { name: 'chainId', type: 'uint256' },
      { name: 'functionSignature', type: 'bytes' },
    ],
  },
  primaryType: 'Intent',
  message: {
    ...intent,
    value: BigInt(intent.value),
    chainId: BigInt(intent.chainId),
  },
});

const { result } = await walletClient.evaluateIntentDirect({
  policyClient,
  intent,
  intentSignature,
  wasmArgs: ['0x', '0x'], // Two pure-Rego policies, in set order
  timeout: 30,
});

console.log(result.allowed); // boolean
console.log(result.task);             // Task object
console.log(result.taskResponse);     // Raw task response
console.log(result.blsSignature);     // BLS signature data
```

**Signature:**

```ts
evaluateIntentDirect(
  args: SubmitEvaluationRequestParams
): Promise<{
  result: {
    allowed: boolean;
    task: Task;
    taskResponse: TaskResponse;
    blsSignature: unknown;
  };
}>
```

**Parameters:**

| Parameter      | Type               | Required | Description                                                                                        |
| -------------- | ------------------ | -------- | -------------------------------------------------------------------------------------------------- |
| `policyClient` | `Address`          | Yes      | The policy client contract address                                                                 |
| `intent`       | `IntentFromParams` | Yes      | The intent to evaluate. `chainId` must be a chain that the client's gateway serves: `11155111` (Ethereum Sepolia), `84532` (Base Sepolia), `46630` (Robinhood Chain testnet) or `5042002` (Arc testnet) on testnet, `1` (Ethereum) or `8453` (Base) on mainnet. |
| `intentSignature` | `Hex`           | No       | EIP-712 signature of the exact intent. Optional in the SDK type, but required by policies and identity flows that read `input.intent_signature`. |
| `timeout`      | `number`           | Yes       | Sent as `timeout`. The gateway accepts it but does not apply it, and ends any HTTP request that runs past its server request timeout (30 seconds in the default configuration) with HTTP 408 |

**Returns:**

- `result.allowed` (`boolean`) -- Whether the intent was allowed by the policy
- `result.task` (`Task`) -- The full task object
- `result.taskResponse` -- The raw task response from the operator
- `result.blsSignature` -- The BLS aggregate signature

A task that fails evaluation throws a plain `Error` with the gateway's reason, and a call the gateway rejects throws a [`GatewayError`](/developers/reference/error-reference#gatewayerror). If `newt_createTask` answers without a `task_response`, the call throws an `SDKError` with code `MALFORMED_RESPONSE`.

:::warning
Identity-backed policies need `intentSignature` even though it is optional in the base request type. Operators recover the signer under the policy client's `eip712Domain()` and load identity data only when that signer is `intent.from`. If you omit the signature, operators skip identity data, and a policy that needs it denies. A signature that is present but does not recover to `intent.from` under the policy client's domain is rejected with HTTP 400 `{"InvalidRequest":"intent_signature does not verify: ..."}`. The gateway rejects a signature that is not hex with `{"InvalidRequest":"intent_signature is not valid hex: <details>"}`.
:::

Read the EIP-712 domain from the policy client whenever possible. Dashboard-deployed clients expose EIP-5267 `eip712Domain()`, which binds the signature to the correct `name`, `version`, `chainId`, and `verifyingContract`.

```ts
import type { Address } from 'viem';

const EIP712_DOMAIN_ABI = [
  {
    type: 'function',
    name: 'eip712Domain',
    stateMutability: 'view',
    inputs: [],
    outputs: [
      { name: 'fields', type: 'bytes1' },
      { name: 'name', type: 'string' },
      { name: 'version', type: 'string' },
      { name: 'chainId', type: 'uint256' },
      { name: 'verifyingContract', type: 'address' },
      { name: 'salt', type: 'bytes32' },
      { name: 'extensions', type: 'uint256[]' },
    ],
  },
] as const;

export async function readEip712Domain(
  policyClient: Address,
  publicClient,
) {
  try {
    const [, name, version, chainId, verifyingContract] =
      await publicClient.readContract({
        address: policyClient,
        abi: EIP712_DOMAIN_ABI,
        functionName: 'eip712Domain',
      });

    return {
      name,
      version,
      chainId: Number(chainId),
      verifyingContract,
    };
  } catch {
    return null;
  }
}
```

If you deploy a custom policy client that does not implement EIP-5267, hardcoded signing domains must match the contract's `EIP712(name, version)` constructor values and the deployed policy client address.

### submitIntentAndSubscribe

Submits a task via `newt_sendTask` and opens a WebSocket connection to receive the evaluation result. Results are intended for use with `validateAttestation` on `NewtonProverTaskManager` (the onchain task verification path).

```ts
const { result, ws } = await walletClient.submitIntentAndSubscribe({
  policyClient: '0x...',
  intent: {
    from: '0x...',
    to: '0x...',
    value: '0x0',
    data: '0x...',
    chainId: 11155111,
    functionSignature: '0x...',
  },
  wasmArgs: ['0x', '0x'], // Two pure-Rego policies, in set order
  timeout: 30,
});

console.log(result.task_id);             // Hex task identifier
console.log(result.subscription_topic);  // WebSocket topic

// Listen for task updates
ws.onmessage = (event) => {
  const message = JSON.parse(event.data);
  if (message.type !== 'update') return; // `subscribed`, `error` and `pong` frames carry no task data
  const update = message.result;
  if (update.event === 'status_update') {
    console.log(update.data.status, update.data.progress, update.data.error);
  } else if (update.event === 'submission_finalized') {
    console.log(update.status, update.transactionHash); // onchain submission outcome
  }
};
```

The SDK opens the socket on the `/ws` path beside the gateway URL, for example `wss://gateway.testnet.newton.xyz/ws`, and subscribes to `result.subscription_topic` once it opens. It sends the API key as a `newton.bearer.<key>` subprotocol beside `newton.v1`, never in the URL. An API key that a subprotocol cannot carry makes the call throw an `SDKError` with code `INVALID_ARGUMENT`. SDK 1.3.1 and earlier send the key in an `api_key` query parameter, which the gateway ignores, so their upgrade fails with HTTP 401.

See [WebSocket Updates](/developers/reference/rpc-api#websocket-updates) for every frame the gateway sends.

:::warning
The gateway does not replay updates: it delivers them only to subscriptions that exist when it publishes them. The SDK subscribes after `newt_sendTask` returns, so `ws` can miss the first updates of a fast task.
:::

**Signature:**

```ts
submitIntentAndSubscribe(
  args: SubmitEvaluationRequestParams
): Promise<{
  result: SubmitIntentResult;
  ws: WebSocket;
}>
```

**Parameters:**

| Parameter      | Type               | Required | Description                                                                                        |
| -------------- | ------------------ | -------- | -------------------------------------------------------------------------------------------------- |
| `policyClient` | `Address`          | Yes      | The policy client contract address                                                                 |
| `intent`       | `IntentFromParams` | Yes      | The intent to evaluate. `chainId` must be a chain that the client's gateway serves: `11155111` (Ethereum Sepolia), `84532` (Base Sepolia), `46630` (Robinhood Chain testnet) or `5042002` (Arc testnet) on testnet, `1` (Ethereum) or `8453` (Base) on mainnet. |
| `timeout`      | `number`           | Yes       | Sent as `timeout`. `newt_sendTask` does not read it                                                |

**Returns:**

- `result.message` (`string`) -- Status message from the gateway
- `result.subscription_topic` (`string`) -- WebSocket topic for task updates: the task ID as lowercase hex without `0x`
- `result.task_id` (`Hex`) -- 32-byte task identifier
- `result.timestamp` (`number`) -- Task creation timestamp
- `ws` (`WebSocket`) -- Active WebSocket connection subscribed to the task topic

**`SubmitIntentResult` type:**

```ts
interface SubmitIntentResult {
  message: string;
  subscription_topic: string;
  task_id: Hex;
  timestamp: number;
}
```

:::note
Use `submitIntentAndSubscribe` when you need onchain task verification via `NewtonProverTaskManager.validateAttestation`. Use `evaluateIntentDirect` for the simpler direct validation path via your policy client's `_validateAttestationDirect`.
:::

### simulateTask

Evaluates the policy client's policy set on the gateway ([newt_simulateTask](/developers/reference/rpc-api#newt_simulatetask)) with oracle outputs you provide in `wasmArgs`. It runs no WASM, creates no task, and collects no operator signatures. The gateway reads the set at the current block, so it can differ from the set a past task was admitted with.

```ts
const result = await walletClient.simulateTask({
  policyClient: '0x...',
  chainId: 11155111,
  intent: {
    from: '0x...',
    to: '0x...',
    value: '0x0',
    data: '0x...',
    chainId: 11155111, // Ethereum Sepolia; 84532, 46630 and 5042002 also work on testnet
    functionSignature: '0x...',
  },
  wasmArgs: ['0x', '0x'], // One slot per policy: its oracle output, or '0x' for pure-Rego
});

console.log(result.success, result.allowed, result.policy_id);
for (const policy of result.policies ?? []) {
  console.log(policy.policy_index, policy.policy, policy.allowed, policy.result);
}
console.log(result.error);
```

`simulateTask` in SDK 1.3.1 and earlier takes `{ intent, policyTaskData }` and sends the old `policy_task_data` request, which the gateway does not accept. Call `newt_simulateTask` directly from those releases.

**Signature:**

```ts
simulateTask(args: SimulateTaskParams): Promise<SimulateTaskResult>
```

### simulatePolicy

Simulates the configured policy set (`newt_simulatePolicy`). The gateway runs each policy's optional WASM and evaluates its Rego, returning per-policy results and an aggregate verdict. It requires deployed policies and a configured client. The pinned gateway checks client ownership, including pure-Rego sets; explicitly authorized admin keys have a read-only bypass.

```ts
const result = await walletClient.simulatePolicy({
  policyClient: '0x...',
  chainId: 11155111,
  intent: {
    from: '0x...', to: '0x...', value: '0x0', data: '0x...',
    chainId: 11155111, functionSignature: '0x...',
  },
  wasmArgs: ['0x', '0x'], // One slot per policy, including pure-Rego entries
});
console.log(result.success, result.allowed, result.policy_id);
for (const policy of result.policies ?? []) {
  console.log(policy.policy_index, policy.policy, policy.allowed, policy.result);
}
```

```ts
simulatePolicy(args: SimulatePolicyParams): Promise<SimulatePolicyResult>
```

`success` means evaluation completed; `allowed` means every policy allowed. Errors have `allowed: null`. This is an unsigned simulation, not an operator quorum or application transaction.

### simulatePolicyData

Simulates one Policy's WASM. No ownership verification is required for caller-supplied secrets. Pass `secrets` as the `envelope` that [`createSecureEnvelope`](#createsecureenvelope) returns, or as its JSON string; the SDK sends it as a SecureEnvelope JSON object. A string that is not JSON makes the call throw an `SDKError` with code `INVALID_ARGUMENT`. SDK 1.3.1 and earlier type `secrets` as a string and send it unchanged, and the gateway answers a string with `success: false` and `secrets is not a valid SecureEnvelope: <details>`.

```ts
const result = await walletClient.simulatePolicyData({
  policyAddress: '0x...',
  wasmArgs: '0x...',
  chainId: 11155111, // required
});

console.log(result.success);
console.log(result.policy_data); // the WASM's JSON output, or null on failure
console.log(result.error);
```

### initialize

Initializes a Newton Policy contract with the given configuration. This is a one-time setup call.

The contract requires `keccak256` of the Rego policy bytes as `_policyCodeHash` so the onchain hash matches the policy referenced by `policyCid`. Provide it one of two ways:

- `policyCodeHash` -- pre-computed hex hash (from `policy_cids.json` or another out-of-band source). Takes precedence when both are set.
- `policyBytes` -- the raw Rego policy bytes; the SDK computes `keccak256` for you. Useful when fetching from IPFS via `policyCid`, reading a local file, or any other transport.

```ts
const txHash = await walletClient.initialize({
  factory: '0x...',
  entrypoint: 'newton/policy/allow',
  policyCid: 'bafyrei...',
  schemaCid: 'bafyrei...',
  wasmCid: '', // empty for a pure-Rego policy
  secretsSchemaCid: '', // empty unless wasmCid is set
  metadataCid: 'bafyrei...',
  owner: '0x...',
  policyBytes: await fetchPolicyBytes(policyCid),
});
```

**Signature:**

```ts
type InitializePolicyArgs = {
  factory: Address;
  entrypoint: string;
  policyCid: string;
  schemaCid: string;
  wasmCid: string;
  secretsSchemaCid: string;
  metadataCid: string;
  owner: Address;
} & ({ policyCodeHash: Hex } | { policyBytes: Uint8Array });

initialize(args: InitializePolicyArgs): Promise<`0x${string}`>
```

**Parameters:**

| Parameter        | Type         | Required          | Description                                                              |
| ---------------- | ------------ | ----------------- | ------------------------------------------------------------------------ |
| `factory`        | `Address`    | Yes               | Address of the deploying factory contract                                |
| `entrypoint`     | `string`     | Yes               | Policy entrypoint path (e.g., `"newton/policy/allow"`)                   |
| `policyCid`      | `string`     | Yes               | Content identifier (CID) of the Rego policy                              |
| `schemaCid`      | `string`     | Yes               | Content identifier (CID) of the policy schema                            |
| `wasmCid`        | `string`     | Yes               | CID of the policy's WASM oracle; empty string for a pure-Rego policy     |
| `secretsSchemaCid` | `string`   | Yes               | CID of the schema for the oracle's secrets; empty string when the oracle needs none |

| `owner`          | `Address`    | Yes               | Owner address of the policy contract                                     |

**Returns:** `` `0x${string}` `` -- The transaction hash.

### renounceOwnership

Renounces ownership of the policy contract. After calling this, no one will be able to perform owner-restricted actions.

:::note

## Privacy Methods

Client-side HPKE encryption for privacy-preserving policy evaluation. These methods are available as wallet client actions and as standalone exports.

:::info
The privacy module uses X25519 KEM + HKDF-SHA256 + ChaCha20-Poly1305 (RFC 9180, Base mode) and is compatible with the Rust gateway implementation.
:::

### `createSecureEnvelope`

Encrypt plaintext into a SecureEnvelope using HPKE. This is a pure offline function — zero network calls. The ephemeral HPKE key is generated internally and zeroed after use.

**Standalone signature:**

```ts
createSecureEnvelope(
  params: CreateSecureEnvelopeParams,
  signingKey: Uint8Array
): Promise<SecureEnvelopeResult>
```

**Wallet client signature:**

```ts
client.createSecureEnvelope(params: CreateSecureEnvelopeParams, signingKey: Uint8Array): Promise<SecureEnvelopeResult>
```

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `params.plaintext` | `Uint8Array \| string \| Record<string, unknown>` | Data to encrypt |
| `params.policyClient` | `Address` | Policy client address this data is scoped to |
| `params.chainId` | `number` | Chain ID for AAD context binding |
| `params.recipientPublicKey` | `string` | Gateway's X25519 public key (hex, no 0x prefix) |
| `signingKey` | `Uint8Array` | Ed25519 private key seed (32 bytes). Caller owns the buffer lifecycle. |

**Returns:** `SecureEnvelopeResult` containing the encrypted envelope, Ed25519 signature, and sender public key.

:::warning
The caller is responsible for zeroing the `signingKey` buffer when done. The function copies the key internally and zeroes the copy after signing, but the original buffer remains in the caller's control.
:::

### `getSecretsPublicKey`

### `uploadConfidentialData`

## Delegator

Submit intents through a `newton-delegator`, which gets them attested and sends the PolicyClient call from its own key, and manage a PolicyClient's delegator set. See the [Delegated Intents guide](/developers/guides/delegated-intents) for the end-to-end flow.

The signing helpers take a plain viem `WalletClient` and need no API key. They are standalone exports and also `newtonWalletClientActions` methods (without the `walletClient` argument).

### `signDelegatedIntent`

Sign `intent` as `intent.from`: the EIP-712 `Intent(address from,address to,uint256 value,bytes data,uint256 chainId,bytes functionSignature)` struct under the domain `{ name: 'NewtonPolicyClient', version: '1', chainId: intent.chainId, verifyingContract: intent.to }`. Throws if the wallet account is not `intent.from`.

```ts
signDelegatedIntent(walletClient: WalletClient, args: { intent: IntentFromParams }): Promise<Hex>
```

### `submitDelegatedIntent`

Sign `intent` and POST it to the delegator. With no `auth`, or the user's own, this needs a delegator that accepts sender submissions; by default only a reader or the PolicyClient's owner may submit.

```ts
submitDelegatedIntent(
  walletClient: WalletClient,
  args: {
    delegatorUrl: string
    intent: IntentFromParams
    wasmArgs?: Hex[]
    auth?: DelegatorAuth
    fetch?: typeof fetch
    abortSignal?: AbortSignal // cancels the POST in flight, not the signature prompt
  },
): Promise<PendingDelegatedIntent>

interface PendingDelegatedIntent {
  intent: DelegatedIntent | DelegatedIntentRef
  created: boolean // false when the delegator already held this signed intent
  signature: Hex
  waitForIntent(params?: WaitForDelegatedIntentParams): Promise<DelegatedIntent> // needs auth
}

// what a resubmission tells a caller that cannot read the intent
interface DelegatedIntentRef {
  intentId: string
  state: DelegatedIntentState
}
```

### `signDelegatorApproval`

Sign, with the delegator key, `DelegatorApproval(uint256 nonce,uint256 deadline)` under the PolicyClient's domain. The owner submits the result with `approveDelegator`. `nonce` defaults to the PolicyClient's current `delegatorNonces(signer)`.

```ts
signDelegatorApproval(
  walletClient: WalletClient,
  args: { policyClient: Address; deadline: bigint; nonce?: bigint },
): Promise<{ signature: Hex; nonce: bigint; deadline: bigint }>
```

### `getDelegatedIntentDigest` / `delegatedIntentTypedData`

`getDelegatedIntentDigest(intent)` returns the PolicyClient's `intentDigest(intent)`: the hash `intent.from` signs, and the key the PolicyClient marks spent. `delegatedIntentTypedData(intent)` returns the typed data (`domain`, `types`, `primaryType`, `message`) for signing it some other way.

```ts
getDelegatedIntentDigest(intent: IntentFromParams): Hex
```

### `createDelegatorClient`

HTTP client for one delegator. `auth` signs each call with an `X-Newton-Auth` header. Every `/v1/*` read needs it, and by default so does `submitIntent`, from a reader or the PolicyClient's owner. Pass `fetch` to add headers for a proxy in front of the delegator. `url` can include the path prefix that a proxy serves the delegator under, such as `https://api.your-app.com/delegator`; calls are signed over the route after it, which is the path the delegator receives.

```ts
const delegator = createDelegatorClient({
  url: 'https://delegator.your-app.com',
  auth: {
    signer: account,          // LocalAccount | WalletClient; a session's account for no wallet prompts
    chainId: 84532,           // the delegator's chain
    session: grant,           // optional: the SignedSessionGrant when signer is a session key
    audience: 'acme.example', // optional: defaults to the URL's hostname
  },
})
```

| Method | HTTP | Returns |
| --- | --- | --- |
| `submitIntent({ intent, signature, wasmArgs?, abortSignal? })` | `POST /v1/intents` | `{ intent: DelegatedIntent \| DelegatedIntentRef; created: boolean }` (see `submitDelegatedIntent`) |
| `getIntent(intentId, { abortSignal? })` | `GET /v1/intents/{id}` | `DelegatedIntent` |
| `listIntents({ policyClient?, sender?, states?, createdAfterMs?, createdBeforeMs?, cursor?, limit?, abortSignal? })` | `GET /v1/intents` | `{ intents: DelegatedIntent[]; nextCursor: string \| null }`, newest first |
| `getAttestation(intentId, { abortSignal? })` | `GET /v1/intents/{id}/attestation` | `{ task, taskResponse, signatureData } \| null` (`null` until attested; a denied intent can return its denying attestation, so check `taskResponse.allowed`; `not_found` for an unknown intent) |
| `getEvents({ after?, limit?, waitMs?, abortSignal?, ...filters })` | `GET /v1/events` | `{ events: DelegatorEvent[]; nextCursor; latestCursor; retentionFloor }` |
| `waitForIntent(intentId, { timeoutMs?, pollIntervalMs?, abortSignal?, until? })` | polls `getIntent` | `DelegatedIntent` once it is at or past a state in `until` (default: `finalized`, `denied` or `failed`); `denied` and `failed` match only themselves, and it rejects if the intent ends short of `until` |

`waitForIntent` rejects with a `DOMException` named `TimeoutError` once `timeoutMs` passes, and with the signal's `reason` when `abortSignal` aborts: a `DOMException` named `AbortError` unless `abort()` was given a reason.

```ts
interface DelegatedIntent {
  intentId: string
  state: 'accepted' | 'attested' | 'tasked' | 'broadcast' | 'included' | 'finalized' | 'denied' | 'failed'
  chainId: number
  policyClient: Address
  from: Address
  idempotencyKey: Hex
  taskId: Hex | null
  executionId: string | null
  taskAttempts: number
  denialReasons: string | null
  terminalError: string | null
  createdAtMs: number
  updatedAtMs: number
  completedAtMs: number | null
}
```

### `createNewtonSession` / `signSessionGrant`

`createNewtonSession(grantor, { expiresInSecs })` makes an ephemeral session key, and the grantor signs one grant for it (one wallet prompt). It returns `{ account, grant }`; pass both as `auth.signer` and `auth.session`. `signSessionGrant(grantor, { sessionKey, expiresAt })` signs a grant for a key you already have. `expiresAt` is in unix seconds.

```ts
createNewtonSession(grantor: LocalAccount | WalletClient, args: { expiresInSecs: number }): Promise<NewtonSession>
signSessionGrant(grantor: LocalAccount | WalletClient, args: { sessionKey: Address; expiresAt: number }): Promise<SignedSessionGrant>
```

### `signNewtonRequest`

Sign a `NewtonRequest` and return the `X-Newton-Auth` header value, for calling the delegator without `createDelegatorClient`. It is signed under the EIP-712 domain `{ name: 'Newton Gateway', version: '1', chainId }`. For the delegator, `method` is `"<VERB> <path>"` with the path as the delegator receives it (percent-encoded, without the query string or a prefix that a proxy strips), and `body` is the exact bytes sent (`''` for a GET).

```ts
signNewtonRequest(
  signer: LocalAccount | WalletClient,
  params: { audience: string; method: string; body: string; chainId?: number; session?: SignedSessionGrant; timestamp?: number },
): Promise<string>
```

### `verifyDelegatorWebhook`

Check a webhook delivery's `X-Newton-Signature` header (`sha256=<hex HMAC-SHA256(secret, body)>`) against the raw request body.

```ts
verifyDelegatorWebhook(args: {
  body: string | Uint8Array
  signature: string | null | undefined
  secret: string
}): Promise<boolean>
```

## Error Handling

The SDK provides structured error classes with typed error codes for precise error handling.

### SDKError

Thrown when the SDK rejects an argument or a gateway response. `code` is an `SDKErrorCode`; [SDKError Codes](/developers/reference/error-reference#sdkerror-codes) lists when the SDK throws each code.

```ts
class SDKError extends Error {
  code: SDKErrorCode;
  rawMessage: string;

  constructor(code: SDKErrorCode, rawMessage: string);
}
```

### GatewayError

Thrown when a gateway JSON-RPC call fails. `code` is the gateway's error variant, such as `AuthorizationFailed` or `RateLimitExceeded`, or `http_error` / `malformed_response`. See [GatewayError](/developers/reference/error-reference#gatewayerror) for every property. SDK 1.3.1 and earlier throw the `error` value from the response body as is, which is not an `Error` instance.

```ts
class GatewayError extends Error {
  method: string;
  status: number;
  code: string;
  rawMessage: string;
  data?: unknown;
  retryAfter?: number;
}
```

### MagicRPCError

Thrown when the Newton Wallet popup returns an error, and with code `UserRejectedAction` when the user closes the popup. Gateway calls throw [`GatewayError`](#gatewayerror) instead.

```ts
class MagicRPCError extends Error {
  code: RPCErrorCode | number;
  rawMessage: string;
  data: unknown;

  constructor(sourceError?: JsonRpcError | null);
}
```

### DelegatorError

Thrown by delegator calls when the delegator answers with a non-2xx status. `code` is the delegator's error code (`invalid_intent`, `idempotency_conflict`, `sender_capacity_exceeded`, ...; see [Delegated Intents](/developers/guides/delegated-intents#errors)). A 2xx answer that is not a JSON object throws with code `malformed_response`, which usually means the URL does not point at a delegator.

```ts
class DelegatorError extends Error {
  status: number;
  code: string;
  rawMessage: string;
  reason?: string; // for 401 unauthorized: why, e.g. 'stale_timestamp'
  details?: unknown;
}
```

## Subpath Exports

The SDK provides multiple entry points for tree-shaking and targeted imports.

| Import Path                                 | Description                                                                       |
| ------------------------------------------- | --------------------------------------------------------------------------------- |
| `@newton-xyz/sdk`          | Full SDK -- all methods, types, utilities, and constants                          |
| `@newton-xyz/sdk/types`    | Type definitions and interfaces only                                              |

:::info
Use subpath exports to minimize bundle size when you only need a subset of SDK functionality.
:::
